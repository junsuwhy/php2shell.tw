## TL;DR

- 兩個 PHP 核心漏洞：<a href={facts.cves[0].advisory}>{facts.cves[0].id}</a>（{facts.cves[0].title}）與 <a href={facts.cves[1].advisory}>{facts.cves[1].id}</a>（{facts.cves[1].title}），官方 CVSS v4.0 都是 {facts.cves[0].cvss_v4}。
- 官方於 2026-10-21 14:00 UTC（台灣時間 22:00）發布修補。所有服務網頁請求的 PHP 安裝都要假設有風險，Apache mod_php 最高。
- 漏洞發生在應用程式碼開始之前，WordPress、Drupal 等應用本身的更新**不是**這次的修補，只能更新 PHP。
- 官方原話：There are no complete mitigations, updating is the only safe choice. 暫時緩解只能降低特定路徑的曝險。
- 更新之後要**重啟所有 worker**，再向正在接流量的行程確認版號。

## 現在立刻做

1. **盤點**：列出所有會回應網頁請求的 PHP，包括控制台（cPanel、Plesk）、Docker 映像、廠商設備與 Windows 軟體內建的 PHP。
2. **確認實際版本**：`php -v` 不一定等於網站在用的 PHP-FPM 或 mod_php，見[是否受影響](/dev/am-i-affected/)。
3. **更新**：依你的平台頁更新到已修補的版本或發行版套件。
4. **重啟**：重啟所有 php-fpm、Apache、LiteSpeed worker；Docker 要重建映像並重新部署。
5. **驗證**：向正在接流量的行程確認版號，滾動更新不要留下舊 worker。
6. **查日誌**：調查視窗從 2026-10-17 起算，見[偵測與應變](/dev/detect/)。
7. **還不能更新**：先套[官方暫時緩解](/dev/mitigation/)，並考慮暫時下線或不直接對外。
