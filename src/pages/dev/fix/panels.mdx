## cPanel（EasyApache 4 的 ea-php）

### 1. 檢查

cPanel 已發布 11/19 的 PHP 安全更新（文章標題寫 November 18, 2026，2026-11-19 18:24 UTC 更新）。EasyApache 4 的修補版，左欄是 11/19 版（含 CVE-2026-115560），右欄是 10 月版作對照：

| 套件 | 11/19 修補版 | 10 月修補版（作對照） |
| --- | --- | --- |
| ea-php85 | 8.5.13 | 8.5.12 |
| ea-php84 | 8.4.28 | 8.4.27 |
| ea-php83 | 8.3.37 | 8.3.36 |
| ea-php82 | 8.2.36 | 8.2.35 |
| ea-php81 | 11/19 文章未列出，待查證 | 8.1.34-5 |
| ea-php80 | 11/19 文章未列出，待查證 | 8.0.30-12 |
| ea-php74 | 7.4.34 | 7.4.33-19 |

cPanel & WHM 自己內部用的 PHP（11/19 文章）：v110 用 PHP 8.1.34；v134、v138 與 WP Squared 用 8.4.28。（10 月時 cPanel & WHM 本身的修補版是 11.110.0.153、11.134.0.66、11.136.0.50、11.138.0.18；WP Squared 為 11.138.1.17。）

注意：11/19 文章內仍寫「CVE IDs have not been published yet」，是發布前留下的舊文字；CVE-2026-115560 其實已公開。用 ea-php81、ea-php80 的，在 cPanel 列出新版前先用[暫時緩解](/dev/mitigation/)的設定。

官方的檢查例子（10 月文章）：查指定 ea-php 套件的變更紀錄裡是否出現 CVE 編號（把 `php81` 換成要查的分支）。11/19 版的 changelog 是否寫上 CVE-2026-115560，本站未查證；請同時確認套件版本達到上表的 11/19 修補版。

<CommandBlock label="cPanel 官方：檢查 ea-php81 是否已含 10 月修補" code={`rpm -q --changelog ea-php81-php-cli | grep -m1 CVE-2026-109618`} />

CloudLinux 主機：cPanel 10 月文章另列 CloudLinux 的 EasyApache 4 與 alt-php，請照 CloudLinux 的公告更新，再用同樣的 changelog 方式確認。

### 2. 更新

11/19 文章的更新步驟：先更新套件庫資料（依作業系統擇一），再更新套件。

<CommandBlock label="cPanel 官方：CentOS／RHEL 系更新套件庫資料" code={`yum clean all && yum makecache`} />

<CommandBlock label="cPanel 官方：Ubuntu 更新套件庫資料" code={`apt clean && apt update`} />

<CommandBlock label="cPanel 官方：更新套件" code={`/scripts/update-packages`} />

cPanel & WHM 內部用的 PHP 會在夜間維護時自動更新；要立刻更新，執行：

<CommandBlock label="cPanel 官方：立即更新 cPanel 內部 PHP" code={`/scripts/autorepair update_cpanel_php8`} />

7.4 以前的 ea-php，10 月文章指向 TuxCare Extended Lifecycle Support，沒有列出對應修補版。

### 3. 重啟

<CommandBlock label="重啟 Apache 與 cPanel 管理的 PHP-FPM" code={`/scripts/restartsrv_httpd
/scripts/restartsrv_apache_php_fpm`} />

### 4. 驗證

對每一個在用的 ea-php 分支重跑上面的 `rpm -q --changelog` 檢查，應該要找得到 CVE 編號；再向網站實際使用的那一版 PHP 確認版本。

## Plesk

### 1. 檢查

隨 Plesk 提供的 PHP 都受影響。Plesk 已發布 11/19 的 PHP 安全更新（含 CVE-2026-115560），修補版：

- Linux 與 Windows 的 8.2 至 8.5：8.5.13、8.4.28、8.3.37、8.2.36。
- Linux 的 8.1.34、8.0.30、7.4.33（已 EOL）：回移植 8.2.36 的安全修補，**版號不變**，要看建置日期。11/19 這批的建置日期，本站未查到，待查證；10 月那批是 2026-10-21 建置。
- Plesk 本身（sw-engine／plesk-engine）：Obsidian 18.0.81 Update 9、18.0.82 Update 4。
- 5.6、7.2、7.3：指向付費的 TuxCare 延長支援。

10 月那次的修補版是 8.5.12、8.4.27、8.3.36、8.2.35（sw-engine 為 18.0.80 Update 11、18.0.81 Update 4），只更新到那一版的請再更新。

官方檢查例子（10 月文章，換成要查的分支）：

<CommandBlock label="Plesk 官方：檢查 8.3 的版本與建置日期" code={`/opt/plesk/php/8.3/bin/php -v`} />

8.2 以上看版號是否達到上面的 11/19 修補版；8.1、8.0、7.4 版號不變，不能只看版號，要看建置日期是否晚於這次更新。

### 2. 更新

把 Plesk 更新到最新，隨附的 PHP 會一起換成修補版。可以在 Plesk 介面的「工具與設定 → 更新」操作，或在主機上執行：

<CommandBlock label="Plesk：安裝所有可用的更新" code={`plesk installer update`} />

### 3. 重啟

更新後確認網頁伺服器與各 PHP 處理程序都已重新啟動，沒有舊的 worker 留著。

### 4. 驗證

對每一個在用的分支重跑 `/opt/plesk/php/<分支>/bin/php -v`，確認版本或建置日期符合上面的修補條件。

## DirectAdmin

DirectAdmin 的 PHP 由 CustomBuild 編譯，更新 CustomBuild 後重新編譯 PHP 即可。DirectAdmin 在 2026-10-21 起發布含 10 月修補的 CustomBuild。含 11/19 版（CVE-2026-115560）的 CustomBuild 狀態，本站在 2026-11-20 查詢時未找到可直接讀的官方來源，待查證；請用下面的 `./build versions` 看可用版本是否已達 8.5.13、8.4.28、8.3.37、8.2.36，還沒有的話先用[暫時緩解](/dev/mitigation/)的設定。

<CommandBlock label="DirectAdmin：更新 CustomBuild、看版本、重新編譯 PHP" code={`cd /usr/local/directadmin/custombuild
./build update
./build versions
./build php`} />

`./build versions` 會列出每個 PHP 槽位目前與可用的版本，編譯完再跑一次確認沒有待更新的項目。8.1 以前的分支修補狀態各槽位不一，見[舊版本策略](/dev/eol/)。編譯完成後重啟網頁伺服器與所有 PHP-FPM 服務，再向正在接流量的那一支 PHP 確認版本。

代管主機的使用者沒有控制台的系統權限時，請直接向主機商要「已更新到哪一版、何時重啟」的明確回覆。
