## 1. 檢查

先確認 PHP 套件從哪裡來：RHEL 的 `php` 套件或模組串流（例如 `php:8.2`），還是 remi 套件庫。兩者處理方式不同。

<CommandBlock label="看已安裝的 PHP 套件與來源套件庫（remi 開頭就是 remi）" code={`dnf list --installed 'php*'
dnf module list --enabled php`} />

再查這個套件是否已含修補：changelog 裡出現 CVE 編號就是已修。

<CommandBlock label="changelog 裡找這次的 CVE（沒有輸出就是還沒修）" code={`rpm -q --changelog php-common | grep -m1 CVE-2026-109618`} />

### Rocky Linux 與 AlmaLinux

兩者都會跟著 RHEL 重建上表的修補套件（AlmaLinux 的版號帶 `.alma`）。更新方式和 RHEL 相同；用上面的 changelog 指令確認有沒有拿到，比看勘誤編號可靠。RHEL 沒有修補的模組串流（例如 RHEL 8 的 php:7.2、php:8.0），重建版也不會有。

### remi 套件庫

remi 在 2026-10-22 發布 8.2.35、8.3.36、8.4.27、8.5.12，涵蓋 Enterprise Linux 8 以上（remi-modular 模組，以及 remi-safe 的平行安裝套件 php82～php85）。8.1 以前 remi 沒有發布修補，見[舊版本策略](/dev/eol/)。

## 2. 更新

<CommandBlock label="RHEL、Rocky、Alma，以及用 remi-modular 的主機：更新 PHP 套件" code={`sudo dnf upgrade --refresh 'php*'`} />

<CommandBlock label="用 remi-safe 平行安裝（例如 php83）的主機" code={`sudo dnf upgrade --refresh 'php83*'`} />

上表狀態仍是 Affected 或 Under investigation 的組合，目前沒有修補可裝：先套[暫時緩解](/dev/mitigation/)、考慮暫時不直接對外，並換到有修補的版本或[自行編譯](/dev/fix/build-from-source/)。

## 3. 重啟

<CommandBlock label="重啟 PHP-FPM 與 Apache（remi-safe 的服務名是 php83-php-fpm 這類）" code={`sudo systemctl restart php-fpm
sudo systemctl restart httpd`} />

**所有** php-fpm 服務都要重啟，讓每一支 worker 都換成新程式。

## 4. 驗證

- 再跑一次第 1 步的 changelog 指令，要找得到 CVE 編號。
- 向正在接流量的那一支 PHP 確認，不只看命令列，見[我受影響嗎？](/dev/am-i-affected/#verify)。
